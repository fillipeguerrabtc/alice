A. Implementar e exportar initializeShutdownManager em @alice/shared-utils
- Criar um gerenciador centralizado e exportá-lo no index do pacote shared-utils. Implementação enterprise-grade: permite registrar etapas com prioridade, executa listeners, garante timeout e logs Pino child.

Arquivo proposto: packages/shared-utils/src/shutdownManager.ts
```typescript name=packages/shared-utils/src/shutdownManager.ts
export type ShutdownHandler = () => Promise<void> | void;

class ShutdownManager {
  private handlers: Map<number, ShutdownHandler[]> = new Map();
  private isShuttingDown = false;
  private timeoutMs = 30_000; // configurable via env if needed

  register(priority: number, handler: ShutdownHandler) {
    if (!this.handlers.has(priority)) this.handlers.set(priority, []);
    this.handlers.get(priority)!.push(handler);
  }

  async initializeShutdownManager(timeoutMs?: number) {
    if (timeoutMs) this.timeoutMs = timeoutMs;
    const doShutdown = async (signal: string) => {
      if (this.isShuttingDown) return;
      this.isShuttingDown = true;
      // eslint-disable-next-line no-console
      console.info(`[ShutdownManager] received ${signal}, starting graceful shutdown`);
      const priorities = Array.from(this.handlers.keys()).sort((a, b) => a - b);
      const start = Date.now();

      for (const p of priorities) {
        const handlers = this.handlers.get(p) ?? [];
        for (const h of handlers) {
          try {
            await Promise.race([h(), new Promise((_, rej) => setTimeout(() => rej(new Error('handler timeout')), this.timeoutMs))]);
          } catch (err) {
            // eslint-disable-next-line no-console
            console.error('[ShutdownManager] handler error:', err);
          }
        }
      }

      const elapsed = Date.now() - start;
      // eslint-disable-next-line no-console
      console.info(`[ShutdownManager] shutdown complete in ${elapsed}ms`);
      // ensure process exit after handlers attempt
      process.exit(0);
    };

    process.once('SIGINT', () => doShutdown('SIGINT'));
    process.once('SIGTERM', () => doShutdown('SIGTERM'));
  }
}

export const shutdownManager = new ShutdownManager();
export const initializeShutdownManager = shutdownManager.initializeShutdownManager.bind(shutdownManager);
export const registerShutdownHandler = shutdownManager.register.bind(shutdownManager);
```

B. Implementar isPoolHealthy utilitário em @alice/shared-utils
- Implementação recomendada: função que aceita um cliente/Pool de pg (node-postgres Pool) e faz uma query simples com timeout; retorna boolean e logs.

Arquivo proposto: packages/shared-utils/src/dbHealth.ts
```typescript name=packages/shared-utils/src/dbHealth.ts
import type { Pool } from 'pg';

export async function isPoolHealthy(pool: Pool, timeoutMs = 2000): Promise<boolean> {
  if (!pool) return false;
  try {
    const client = await Promise.race([
      pool.connect(),
      new Promise<never>((_, rej) => setTimeout(() => rej(new Error('db connect timeout')), timeoutMs)),
    ]) as Awaited<ReturnType<Pool['connect']>>;
    try {
      await Promise.race([
        client.query('SELECT 1'),
        new Promise<never>((_, rej) => setTimeout(() => rej(new Error('db query timeout')), timeoutMs)),
      ]);
      return true;
    } finally {
      client.release();
    }
  } catch (err) {
    // eslint-disable-next-line no-console
    console.error('[dbHealth] pool not healthy', err);
    return false;
  }
}
```

D. Abordagem para TS2589 (Type instantiation excessively deep)
- Estratégia: identificar as linhas reportadas (fornecidas nos logs) e aplicar uma das duas ações:
  1) Substituir tipos inferidos complexos por aliases nomeados simples (Rule 7: mudanças cirúrgicas).
  2) Fornecer anotações explícitas ao usar generics de hooks (ex.: useQuery<TData, TError>), evitar uso de Zod.infer<...> diretamente em props quando a inferência encadeada é complexa.

Exemplo genérico (padrão para páginas Agents / ModulesAdmin / Namespaces):
- Identifique o tipo que está causando expansão (ex.: Resultado de fetchAgentsResponse).
- Crie um alias simples em um arquivo de tipos compartilhado (packages/shared-utils/src/types.ts ou apps/frontend-service/src/types.ts):

```typescript name=apps/frontend-service/src/types/agents.ts
export interface AgentSummary {
  id: string;
  name: string;
  status: 'active' | 'inactive' | 'unknown';
  tenantId?: string;
  // campos necessários apenas para UI; mantenha mínimo
}
```

- Use o alias explicitamente no componente:
```tsx name=apps/frontend-service/src/pages/Agents.tsx
import type { AgentSummary } from '../types/agents';

const AgentsPage: React.FC = () => {
  const { data } = useQuery<AgentSummary[], Error>(['agents'], fetchAgents);
  // ...
}
```

Motivação: forçar inferência limitada, reduzir recursão do compilador e manter strict typing.

Observação prática: se o problema for causado por utilitários de Zod e transformação tipo->io, prefira criar tipos TypeScript explícitos e usar safeParse retornos em runtime.
