Resumo executivo do problema encontrado
- Erro principal no log: TS6305: "Output file '/app/packages/shared/dist/index.d.ts' has not been built from source file '/app/packages/shared/src/index.ts'".
- Causa mais provável: o pacote @alice/database está sendo compilado isoladamente com tsc -b, mas depende (por referências de projeto) do pacote @alice/shared. Como @alice/shared não foi compilado antes, os arquivos .d.ts esperados não existem → tsc falha.
- Correção geral: garantir que os pacotes dependentes (shared) sejam construídos antes do pacote que os consome. Em monorepos TypeScript com project references, execute o build a partir da raiz (tsc -b com tsconfig.root.json que referencia os pacotes) ou execute build recursivo do workspace pnpm (-w -r build) para respeitar dependências.

```yaml name=.github/workflows/deploy-production.yml
on:
  push:
    branches: [ main ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'pnpm'
      - name: Setup pnpm
        run: corepack enable && corepack prepare pnpm@latest --activate
      - name: Restore cache
        uses: actions/cache@v4
        with:
          path: ~/.pnpm-store
          key: ${{ runner.os }}-pnpm-${{ hashFiles('**/pnpm-lock.yaml') }}
      - name: Install
        run: pnpm install --frozen-lockfile
      - name: Build workspace (respect project references)
        run: pnpm -w -r build
      # continue with build/publish image steps...
```

Por que isso resolve TS6305
- Quando você usa project references e "composite": true, o tsc -b executado na raiz (ou execução recursiva de build dos pacotes) garante que os arquivos .d.ts do projeto shared sejam gerados antes de compilar database. O erro TS6305 ocorre quando tsc para database espera o .d.ts do shared e não o encontra.

Comandos para reproduzir localmente
- No root:
  - pnpm install
  - pnpm -w -r build
  - ou: tsc -b (se você configurou tsconfig.root com references)

Verificações adicionais e melhorias (senior)
- Verifique se em cada package/package.json você tem "types": "dist/index.d.ts" apontando para a saída correta.
- Garanta que o lockfile (pnpm-lock.yaml) seja preservado e use --frozen-lockfile na CI.
