1) packages/shared/package.json
- Garantir que o pacote shared declare main/types e script de build.

Copiar/colar:
{
  "name": "@alice/shared",
  "version": "1.0.0",
  "main": "dist/index.js",
  "types": "dist/index.d.ts",
  "scripts": {
    "build": "tsc -b",
    "clean": "rimraf dist"
  },
  "files": [
    "dist"
  ]
}

2) packages/shared/tsconfig.json
- Habilitar declarations e composite (para project references).

Copiar/colar:
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "CommonJS",
    "declaration": true,
    "declarationMap": true,
    "composite": true,
    "outDir": "dist",
    "rootDir": "src",
    "esModuleInterop": true,
    "skipLibCheck": true
  },
  "include": ["src/**/*"]
}

3) packages/shared/src/index.ts
- Exportar o que o database importa (se o database importa '@alice/shared/schema', disponibilize esse export via index).

Exemplo simples (copiar/colar):
export * from './schema';

Se seu schema estiver em src/schema.ts ou src/schema/index.ts, ajuste o caminho conforme necessário.

4) packages/database/package.json
- Declarar dependência local no shared usando workspace:* para que pnpm resolva corretamente.

Copiar/colar (apenas a seção relevante ou substitua o arquivo completo):
{
  "name": "@alice/database",
  "version": "1.0.0",
  "main": "dist/index.js",
  "types": "dist/index.d.ts",
  "scripts": {
    "build": "tsc -b",
    "clean": "rimraf dist"
  },
  "dependencies": {
    "@alice/shared": "workspace:*"
  }
}

5) packages/database/tsconfig.json
- Add project reference para shared (para que tsc saiba construir na ordem correta).

Copiar/colar:
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "dist",
    "rootDir": "src"
  },
  "references": [
    { "path": "../shared" }
  ],
  "include": ["src/**/*"]
}

6) (Opcional mas recomendado) root tsconfig.json (ou tsconfig.base.json)
- Mapear paths para ajudar IDE/tsc em imports absolutos.

Copiar/colar:
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@alice/*": ["packages/*/src"],
      "@alice/shared": ["packages/shared/src"],
      "@alice/shared/*": ["packages/shared/src/*"]
    }
  },
  "references": [
    { "path": "packages/shared" },
    { "path": "packages/database" }
  ]
}

7) Ajuste do import em packages/database/src/index.ts (se atualmente usa '@alice/shared/schema')
- Duas opções:
  a) manter import original, mas garantir que shared exporte subpath schema;
  b) ou simplificar para importar do pacote raiz do shared.

Exemplo (copiar/colar) — mudar isto:
import { MySchema } from '@alice/shared/schema';

Para isto (mais simples):
import { MySchema } from '@alice/shared';

8) Dockerfile — garantir build do shared antes do database
- Substitua a linha que só builda database por um comando que builda shared primeiro, depois database.

Substituir (linha problemática):
RUN pnpm --filter @alice/database run build

Por (copiar/colar):
RUN pnpm --filter @alice/shared run build && pnpm --filter @alice/database run build

Alternativa (build todos em ordem topológica):
RUN pnpm -w -r run build --workspace-root

(obs: se usar pnpm recursive paralelo, você pode precisar forçar ordem — a primeira opção é a mais simples e determinística)

9) Garantir que a compilação do shared realmente gera .d.ts
- Verifique em packages/shared/tsconfig.json que "declaration": true e que os arquivos gerados ficam em dist/.
- Se usar tsc -b via project references isso já gera .d.ts para outros projetos consumirem.

10) Verificação final local
- No root do repositório execute localmente para validar:
pnpm install
pnpm --filter @alice/shared run build
pnpm --filter @alice/database run build

ou apenas:
pnpm -w -r run build

Se a compilação local passar, atualize o Dockerfile e reexecute a Action.
