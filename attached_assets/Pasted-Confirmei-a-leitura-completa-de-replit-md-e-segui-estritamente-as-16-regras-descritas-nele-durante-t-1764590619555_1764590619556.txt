1) Erro: isPoolHealthy ausente (TS2304)
- Sintoma: três serviços referenciam isPoolHealthy sem definição/export.
- Impacto: impede build/typecheck — serviços que dependem da verificação de pool não compilam.
- Recomendação (cirúrgica, enterprise):
  - Implementar utilitário dbHealth.isPoolHealthy que: faz connect com timeout, executa SELECT 1, libera client, retorna boolean. Logs com Pino.
  - Exportar do pacote @alice/shared-utils.
- Código sugerido (crítico — adicione a este package): 

```typescript name=packages/shared-utils/src/dbHealth.ts
import type { Pool } from 'pg';
import pino from 'pino';

const logger = pino().child({ module: 'shared-utils/dbHealth' });

export async function isPoolHealthy(pool: Pool, timeoutMs = 2000): Promise<boolean> {
  if (!pool) {
    logger.error('isPoolHealthy called with no pool');
    return false;
  }
  try {
    const client = await Promise.race([
      pool.connect(),
      new Promise<never>((_, rej) => setTimeout(() => rej(new Error('db connect timeout')), timeoutMs)),
    ]) as Awaited<ReturnType<Pool['connect']>>;
    try {
      await Promise.race([
        client.query('SELECT 1'),
        new Promise<never>((_, rej) => setTimeout(() => rej(new Error('db query timeout')), timeoutMs)),
      ]);
      logger.debug('DB pool healthy');
      return true;
    } finally {
      client.release();
    }
  } catch (err) {
    logger.warn({ err }, 'DB pool not healthy');
    return false;
  }
}
```

2) Erro: initializeShutdownManager não exportado (TS2305)
- Sintoma: server/index-prod.ts importa initializeShutdownManager de @alice/shared-utils, mas não existe export.
- Impacto: sem gerenciador central de shutdown, graceful shutdown e ordem de parada ficam inconsistentes — viola requisito enterprise (replit.md).
- Recomendação: Implementar ShutdownManager central, com registro de handlers por prioridade, timeout configurável, logs Pino e binding dos sinais SIGINT/SIGTERM. Exportar initializeShutdownManager e registerShutdownHandler no shared-utils.
- Código sugerido:

```typescript name=packages/shared-utils/src/shutdownManager.ts
export type ShutdownHandler = () => Promise<void> | void;

class ShutdownManager {
  private handlers = new Map<number, ShutdownHandler[]>();
  private shutting = false;
  private timeoutMs = Number(process.env.SHUTDOWN_TIMEOUT_MS) || 30_000;

  register(priority: number, handler: ShutdownHandler) {
    const arr = this.handlers.get(priority) ?? [];
    arr.push(handler);
    this.handlers.set(priority, arr);
  }

  async initializeShutdownManager() {
    const run = async (signal: string) => {
      if (this.shutting) return;
      this.shutting = true;
      // Pino logs should be used at runtime; using console here if logger not initialized yet.
      // Prefer injecting logger in production bootstrap.
      console.info(`[ShutdownManager] received ${signal}, starting shutdown`);
      const priorities = Array.from(this.handlers.keys()).sort((a, b) => a - b);
      const start = Date.now();
      for (const p of priorities) {
        const handlers = this.handlers.get(p) ?? [];
        for (const h of handlers) {
          try {
            await Promise.race([h(), new Promise((_, rej) => setTimeout(() => rej(new Error('handler timeout')), this.timeoutMs))]);
          } catch (err) {
            console.error('[ShutdownManager] handler error', err);
          }
        }
      }
      const elapsed = Date.now() - start;
      console.info(`[ShutdownManager] shutdown complete in ${elapsed}ms`);
      process.exit(0);
    };

    process.once('SIGINT', () => run('SIGINT'));
    process.once('SIGTERM', () => run('SIGTERM'));
  }
}

export const shutdownManager = new ShutdownManager();
export const initializeShutdownManager = shutdownManager.initializeShutdownManager.bind(shutdownManager);
export const registerShutdownHandler = shutdownManager.register.bind(shutdownManager);
```

3) TS2589: Type instantiation excessively deep (frontend/client)
- Sintoma: páginas Agents.tsx, ModulesAdmin.tsx, Namespaces.tsx aparecem no log com erro TS2589.
- Causa provável: tipos genéricos recursivos (ex.: Zod.infer aninhado, axios response types encadeados) ou autoinferência complexa de hooks.
- Impacto: impede compilação do frontend; pode durar muito para o compilador resolver.
- Recomendações práticas:
  - Criar aliases de tipos TS explícitos (ex.: AgentSummary, ModuleSummary) e usar generics explícitos em hooks (useQuery<TData, TError>).
  - Evitar usar Zod.infer<> diretamente em props/JSX — materializar tipos em interfaces nomeadas.
  - Se usar utilitários complexos (Mapped types, Conditional types), simplifique ou quebre em tipos menores.
  - Como mitigação segura: dividir componentes grandes em menores para reduzir inferência por componente.
- Exemplo de correção (padrão):

```typescript name=apps/frontend-service/src/types/agent.ts
export interface AgentSummary {
  id: string;
  name: string;
  status: 'active' | 'inactive' | 'error';
  tenantId?: string;
}
```

e no componente:

```tsx
const { data } = useQuery<AgentSummary[], Error>(['agents'], fetchAgents);
```
