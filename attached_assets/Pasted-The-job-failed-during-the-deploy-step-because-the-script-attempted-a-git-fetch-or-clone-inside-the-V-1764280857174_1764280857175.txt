The job failed during the deploy step because the script attempted a git fetch or clone inside the VM but could not read the GitHub username, resulting in the error:
```
fatal: could not read Username for 'https://github.com': No such device or address
```

Root cause:
The deploy script intends to use header-based authentication for git operations with:
```bash
GH_AUTH_HEADER="Authorization: Bearer ${{ secrets.GH_PAT }}"
git -c "http.extraHeader=${GH_AUTH_HEADER}" fetch origin
```
However, this fails if `${{ secrets.GH_PAT }}` is not set, missing, or malformed. The logs show the error, which indicates the authentication mechanism isn’t working as expected inside the VM.

Solution:
1. Ensure that the GitHub Personal Access Token (`GH_PAT`) is correctly configured in your repository secrets. It must have at least `repo` scope for private repositories.
2. In your workflow and secrets settings:
   - Double-check the secret is named `GH_PAT` and contains a valid token.
   - Confirm it's passed to the script via `${{ secrets.GH_PAT }}`.

3. Optionally, update your script error handling for better visibility:
```bash
if [ -z "${{ secrets.GH_PAT }}" ]; then
  echo "❌ GH_PAT GitHub token está vazio. Configure um token válido nos secrets do repositório!"
  exit 1
fi
```

4. If you want to avoid header-based authentication, use a deploy key with read permissions, or use the default GitHub Actions token (`GITHUB_TOKEN`) for workflows that only need read access.

After setting/reviewing the secret, the deploy should succeed when fetching or cloning the repository during deployment.
